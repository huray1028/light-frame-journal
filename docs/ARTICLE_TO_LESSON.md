# 將攝影文章轉成短教程與練習

這份文件說明使用者如何把網路上學到的新知識交給 Agent，並讓 Agent 依專案規範整合進網站。

## 使用方式

提供一個可讀取的文章網址或貼上內容，並告訴 Agent：

```text
閱讀 AGENTS.md，把這篇攝影文章加入知識庫。
請保留作者與來源，不要大量照抄；先檢查是否已有相同概念，
再把適合的部分整理成一小段教程和可實際拍攝的練習。
更新來源紀錄、Wiki、課程順序與網站，最後執行驗證。
```

若文章只適合補充既有課程，可以再加一句：

```text
如果主題已存在，優先更新原本課程，不要為了新增而建立重複頁面。
```

## Agent 應完成的成果

1. `raw/sources/YYYY-MM-DD-<source-slug>.md`：來源資訊、摘要、限制與處理狀態。
2. `wiki/concepts/<concept>.md`：整合新舊來源，標出一致、矛盾與待驗證之處。
3. `content/lessons.json`：建立或更新短教程、練習與 `sources`。
4. `wiki/index.md`：新增來源或概念索引。
5. `wiki/log.md`：記錄本次 ingest 與受影響頁面。
6. 驗證結果：schema、slug、order、來源路徑、關聯與頁面呈現。

## 教程品質判斷

合格的短教程不是文章縮寫，而是把知識變成行動：

- **情境**：什麼時候會用到？
- **決定**：拍攝者需要選擇什麼？
- **操作**：在相機或現場具體做什麼？
- **觀察**：如何看出改變造成的差異？
- **錯誤**：哪些口訣可能因條件不同而失效？
- **練習**：改變一個變因、保持其他條件、比較結果並寫回日誌。

## 來源與著作權

- 以摘要、轉述、比較與教學重組為主。
- 不保存或公開未授權文章全文。
- 必要短引文需標示來源，且只引用支持觀點所需的最短範圍。
- 不把來源作者的作品、測試照片或個人結果冒充成本站實拍成果。
- 無法確認的器材功能或技術主張標示為待驗證，不以肯定語氣發布。

## 完成後回報格式

```text
來源：<標題與作者>
處理方式：新增教程／更新既有教程／只更新概念頁
衍生 slug：<lesson-slug>
新增練習：<一句話>
仍待驗證：<條件或問題>
異動檔案：<清單>
驗證結果：通過／未通過與原因
```
